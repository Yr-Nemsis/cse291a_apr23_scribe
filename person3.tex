
\section{Estimate size: Popular floating point standards}
The precision format determines how many bytes are needed to store each value.
In deep learning, this directly affects model memory, activation memory, and bandwidth.
\begin{itemize}
    \item FP32: 32 bits $= 4$ bytes per value.
    \item FP16: 16 bits $= 2$ bytes per value. It has fewer exponent bits than FP32, so the dynamic range is smaller.
    \item BF16: 16 bits $= 2$ bytes per value. It keeps the same exponent width as FP32 but uses fewer fraction bits, so it has lower precision but similar dynamic range.
\end{itemize}
In practice, FP16 and BF16 are common because they reduce memory by about $2\times$ compared with FP32.
\section{Estimate the weight size: GPT3}
Weight size depends on the total number of parameters and the number of bytes per parameter:
\[
\text{Weight memory} = N_{\text{params}} \times \text{bytes per parameter}.
\]
If GPT-3 has $N$ parameters and we store weights in FP16/BF16, then:
\[
\text{Weight memory} \approx N \times 2 \text{ bytes}.
\]
For FP32, it would be $N \times 4$ bytes.
Note that batch size does not change the weight size; batch size mainly affects activation memory.
\section{Estimate the activation size}
The parameter (or tensor) size is computed as the number of elements multiplied by the storage size of each element, which is usually 2 bytes (FP16) or 4 bytes (FP32), depending on the precision. Here, $bs$ means batch size, $nc$ means number of channels, and $w_o, h_o$ are the output width and height. Therefore, the activation size is
\[
bs \times nc \times w_o \times h_o \times \text{sizeof(element)}.
\]
\section{Estimate the activation size: MLP}
For an MLP layer, the output is computed as:
\[
C = XW,
\]
The output activation has $(bs \cdot m)\times p$ elements, so:
\[
\text{Activation memory} = bs \times m \times p \times \text{bytes per element}.
\]
The activation memory scales linearly with batch size because each input example contributes its own output activations.
